# Later Space 账户、新手引导与迁移实施计划

依据：`docs/superpowers/specs/2026-09-03-account-onboarding-migration-design.md`

## 阶段 1：锁定账户与迁移契约

1. 新增账户体验契约测试，覆盖独立登录页、访客入口、账户头像和画布引导。
2. 新增迁移状态测试，覆盖 `available`、`deferred`、`pending`、`complete` 与 `undone`。
3. 明确登录不自动迁移，未校验完成不隐藏本机源数据。

## 阶段 2：建立正式登录与账户入口

1. 把当前新手浮层改为独立欢迎登录页，复用现有 Supabase 邮箱免密能力。
2. 支持“先体验 Later Space”，并记住用户已完成首次选择。
3. 登录后在右上角显示头像、昵称和同步状态；未登录时显示明确的登录入口。
4. 新增“我的”账户面板，承载资料、数据同步、容量、插件和手机入口。

## 阶段 3：把使用说明放进画布

1. 新增三张只存在于界面的画布引导卡，不写入 IndexedDB。
2. 用户粘贴第一条内容后自动隐藏，并支持手动关闭。
3. 验证引导卡不进入搜索、筛选、计数、备份或同步。

## 阶段 4：重构安全迁移流程

1. 登录后只检测访客收藏，不自动创建账号副本。
2. 首次检测到旧数据时显示迁移提示，支持“迁移到当前账号”和“暂时不迁移”。
3. `deferred` 状态不重复弹窗，但“我的 → 数据与同步”始终保留迁移入口。
4. 迁移前统计类型、图片容量、重复项和暂不支持项。
5. 批次迁移支持进度、取消、断点恢复和重复跳过；校验成功后才隐藏访客源数据。
6. 迁移完成后保留 30 天撤销；撤销只处理本批次副本。

## 阶段 5：视觉、回归与发布准备

1. 在桌面和手机视口验证欢迎页、画布引导、账户面板和迁移页面。
2. 运行 JavaScript 语法检查、Python 全量测试和 diff 检查。
3. 使用空白测试工作区验证新用户，并使用临时测试数据验证旧用户迁移，不触碰真实收藏。
4. 用户确认视觉后再提交功能代码并部署。

## 提交策略

- 当前工作区已有云同步、iOS 和插件相关未提交内容；本轮不重置、不覆盖。
- 实施时只暂存本轮明确修改的文件和测试。
- 正式部署前先给用户本地预览，不自动推送线上。
