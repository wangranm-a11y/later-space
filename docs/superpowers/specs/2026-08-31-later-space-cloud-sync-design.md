# Later Space 云端同步第一版设计

日期：2026-08-31  
状态：已自检，待用户确认  
范围：Web + iPhone 快捷指令 + Supabase

## 1. 目标

Later Space 第一版云端能力要让普通用户在不了解 Supabase 的情况下完成注册、收藏和多设备同步。用户可以不登录直接使用；登录后，本机已有内容默认安全迁移到云端。第一版只支持网页链接、文字和图片。

成功标准：

- 未登录用户可以立即收藏，关闭网页或重启浏览器后内容仍在当前浏览器中。
- 登录用户在 Mac、iPhone 和其他浏览器中看到同一账号的内容。
- 手机快捷指令在 Mac 关机、离开同一局域网时仍能直接写入云端。
- 只有云端确实保存成功后，手机才显示成功通知。
- 图片以清晰优化版保存和导出；不承诺保留原图、原始尺寸或元数据。
- 个人或系统图片空间达到 85% 后阻止新增图片，但查看、导出、删除、文字和链接继续可用。
- 用户之间的数据、媒体和收件密钥完全隔离。

## 2. 非目标

第一版不实现：

- 视频同步。
- 原图云备份。
- App Store 原生 App。
- 普通用户自带 Supabase 项目。
- 团队空间、公开分享、付费订阅和复杂管理员后台。
- Safari 或 Chrome 书签导入。本文所说的“本机内容”只指未登录时保存在 Later Space 当前浏览器里的内容。

## 3. 用户需要理解的核心区别

产品内 onboarding、帮助页面和后续 PPT 都必须说明：

```text
不登录：内容只保存在当前设备的当前浏览器，不能多端同步，清除网站数据后可能丢失。
登录：Supabase 保存正式云端副本，各设备保留本机缓存，可离线操作并在联网后同步。
```

“云端同步”是 Later Space 提供给用户的产品功能；Supabase 是实现账号、数据库、媒体存储和云端收件的底层服务。它们不是两套不同的同步功能。

## 4. 总体架构

```text
Web / PWA ───────────────┐
                         ├─ Supabase Auth
iPhone 快捷指令 → Edge Function ├─ Postgres + RLS
                         └─ Private Storage
其他浏览器 ──────────────┘
```

- Web 使用 IndexedDB 作为本地优先缓存，保证立即收藏、快速打开和短期离线操作。
- Supabase Auth 使用 Email Magic Link。用户注册 Later Space 即可，不需要注册或配置 Supabase。
- Postgres 保存链接、文字、卡片元数据、同步版本、删除标记和媒体计量信息。
- Private Storage 只保存优化后的图片文件，路径必须以用户 ID 开头。
- Edge Function 接收手机快捷指令内容、验证个人收件密钥、规范化类型、检查容量、验证并在需要时再次优化图片，然后写入用户空间。
- Supabase Realtime 通知在线页面有内容变化；页面获得焦点和每 30 秒轮询作为补偿机制。

## 5. 本地访客模式与账号工作区

IndexedDB 中的记录必须带 `workspace_id`：

- `guest:<browser-id>`：当前浏览器的未登录空间。
- `user:<supabase-user-id>`：某个登录账号的本机缓存。

应用始终只展示当前工作区，防止同一浏览器上不同账号的数据混在一起。

### 5.1 未登录

- 新增、编辑和删除只写当前 guest 工作区。
- 正常关闭网页、退出浏览器或重启设备不会删除数据。
- UI 明确提示“仅保存在当前浏览器”；不使用恐吓式弹窗。
- 清除网站数据、无痕模式、卸载浏览器、设备损坏或浏览器主动清理存储仍可能导致内容丢失。

### 5.2 登录

- 所有更改先写 `user:<id>` 本地工作区，再加入云端队列。
- 离线时显示“等待同步”，联网后自动重试。
- 云端是登录账号的正式跨设备副本，本地工作区是缓存和离线副本。

### 5.3 退出账号

- 撤销 Supabase 登录会话。
- 删除本设备的 `user:<id>` 缓存、下载媒体对象 URL 和账号级同步状态，防止共用电脑泄露内容。
- 不删除 Supabase 云端内容。
- 切回原来的 guest 工作区；若不存在则展示空白本地空间。
- 用户再次登录后从云端重新下载账号数据。

“关闭网页”“退出账号”“删除账号”必须使用不同文案。删除账号是独立的危险操作，第一版不放在主要流程中。

## 6. 首次登录自动迁移

用户首次登录后，如果 guest 工作区有 Later Space 内容，系统默认开始迁移，不先弹“是/否”阻断用户：

```text
发现本机内容 → 复制到账号工作区 → 上传云端 → 验证成功 → 隐藏 guest 副本
```

界面显示轻量进度条和两个可逆入口：

- 迁移进行中：“正在带入 18 / 26 条” + “取消”。
- 迁移完成：“已带入 26 条本机内容” + “撤销”。

安全规则：

- 迁移是先复制、验证后隐藏，不在上传前删除 guest 原始记录。
- 每条记录保存迁移状态和目标用户 ID，重载页面后可以续传且不会重复。
- 用户取消时，停止未上传项目；本次已经上传的迁移副本统一软删除，guest 内容重新显示。
- 用户撤销时，云端迁移副本软删除，guest 内容重新显示。
- 隐藏的 guest 原始记录保留 30 天用于撤销，之后才清理。
- 容量不足时，文字和链接继续迁移；图片停在队列中并显示需要清理的数量。

## 7. 数据与同步模型

沿用 `later_space_items` 作为账号内容主表，并做以下调整：

- `kind` 第一版对外只允许 `image`、`link`、`text`。
- `data` 保存卡片标题、正文、URL、标签、位置、样式和来源。
- `asset_path` 指向用户私有图片。
- `asset_bytes` 保存优化图片的实际字节数。
- `client_updated_at` 和 `server_updated_at` 用于版本比较和增量拉取。
- `deleted_at` 实现软删除，避免另一台离线设备把已删除内容重新上传。

新增三个职责单一的数据单元：

1. `later_space_capture_tokens`：保存个人手机收件密钥的哈希、提示后四位、最近使用时间和撤销时间；永不保存明文密钥。
2. `later_space_usage`：保存每位用户已用图片字节、个人额度和更新时间。
3. `later_space_system_config`：保存系统图片总额度、70%/80%/85% 阈值和是否接受图片上传。

所有用户表开启 RLS。用户只能读取和修改自己的内容、用量与收件密钥。系统总用量只允许管理员或 Edge Function 的服务角色读取和更新。`service_role` 密钥只能存在于 Supabase 服务端秘密变量中，不能进入网页、快捷指令、Git 或公开文档。

### 7.1 同步规则

- 不同记录直接合并。
- 同一记录以较新的 `client_updated_at` 为准。
- 时间相同时，删除状态优先于未删除状态。
- 保存成功的本地操作从队列移除；失败操作保留并指数退避重试。
- Realtime 事件只作为“有变化”的信号，客户端收到后仍通过带 RLS 的 API 拉取正式行。
- 页面重新获得焦点时立即拉取；Realtime 不可用时每 30 秒轮询。

## 8. 图片优化、导出与隐私

第一版只保存清晰优化版：

- 最长边不超过 1920 px。
- 根据内容转换为适合的 WebP 或 JPEG；默认目标质量约 82%，实际结果以可读性优先。
- 客户端先尝试优化原始图片；进入云端上传接口的优化结果不得超过 5 MB，仍超限则给出明确错误。
- 网页上传在浏览器中优化；手机快捷指令入口由预配置快捷指令完成必要转换，Edge Function 再验证尺寸、类型和结果。
- 服务端只接受 JPEG、PNG 和 WebP 优化结果；iPhone HEIC 由快捷指令先转换为 JPEG，避免要求普通用户手工添加动作。
- 删除 EXIF 等不影响显示的元数据，减少体积和位置隐私风险。

导出返回云端保存的优化版，不声称或尝试恢复原始文件。导出界面使用“导出清晰优化版”文案。

## 9. 容量保护

Supabase Free 的 1 GB Storage 是项目内所有用户共享的总额度，不会自动平均分配。Later Space 在应用层设置双重保护：

- 每位免费用户默认图片额度：50 MB。
- 系统总图片额度：按部署环境配置；免费 Supabase 初始设为 1 GB。
- 70%：温和提醒。
- 80%：持续醒目的清理提醒。
- 85%：图片硬上限。

图片上传必须同时满足：

```text
个人已用 + 新图片 <= 个人额度的 85%
系统已用 + 新图片 <= 系统额度的 85%
```

达到上限时：

- 禁止新增和替换图片。
- 继续允许查看、导出、删除图片。
- 继续允许新增、编辑和同步文字及链接。
- 删除图片并使占用回落到 85% 以下后立即恢复上传。

提醒对象：

- 个人达到 70%、80% 时，只提醒该用户。
- 个人达到 85% 时，该用户收到明确阻止原因和清理入口。
- 系统达到 70%、80%、85% 时提醒管理员。
- 系统达到 80%、85% 时也向尝试上传图片的用户说明“系统图片空间接近上限”，但不暴露其他用户信息。

所有图片写入必须经过一个带数据库锁的服务端容量检查，避免多个并发上传共同越过上限。上传完成后记录实际 `asset_bytes`；替换和删除图片时同步增减计量。失败上传清理孤儿文件。管理员可以运行计量校准操作，用 Storage 实际文件清单纠正异常值。

## 10. 手机快捷收件

每位登录用户在网页中点击“连接手机快捷收件”后生成一枚高熵个人收件密钥。网页展示：

- 一键复制的个人收件地址。
- 安装预配置快捷指令的入口。
- 最近一次成功收件时间。
- “重新生成密钥”和“停用手机收件”。

公开用户不需要自己搭建快捷指令动作。发布前由项目维护者在 iPhone 上验证并分享一个预配置模板；用户只需安装模板并粘贴一次个人收件地址。

快捷指令接收系统分享面板中的链接、文字和图片：

- Safari 网页先提取真实 URL，不把整页 HTML 当作文字上传。
- 纯文字按 UTF-8 文本发送。
- 图片先转换为 JPEG、限制最长边和体积，再作为文件发送。
- Edge Function 验证密钥、内容类型、大小和容量，再写入对应用户。

Edge Function 成功时返回用户可直接阅读的短消息，例如“已收进 Later Space”。快捷指令的通知内容必须使用服务器返回值，禁止固定显示成功。HTTP 非成功响应会阻止成功通知并显示明确原因。

密钥可以随时撤销；撤销不影响账号密码和既有内容。服务端对单个密钥和 IP 设置速率限制，重复内容使用内容指纹去重。

## 11. 错误与恢复

错误信息面向普通用户，说明发生了什么以及下一步做什么：

| 场景 | 用户提示 | 数据处理 |
|---|---|---|
| 临时断网 | 网络不可用，已保存在本机，联网后会继续同步 | 保留本地队列 |
| 登录过期 | 请重新登录以继续同步 | 不删除本地账号缓存，重新认证后续传 |
| 个人空间 85% | 你的图片空间已满，请先删除一些图片 | 拒绝图片，文字和链接继续 |
| 系统空间 85% | Later Space 图片空间暂时已满，仍可收藏文字和链接 | 拒绝图片并提醒管理员 |
| 不支持的格式 | 这张图片暂时无法处理，请换成 JPG、PNG 或截图 | 不创建成功记录 |
| 云端写入失败 | 没有保存成功，请稍后重试 | 手机不显示成功；网页保留队列 |
| 重复内容 | 这条内容已经在 Later Space 里 | 返回已有项目，不重复占用空间 |

系统必须记录不含内容正文和图片数据的诊断日志，包括请求 ID、用户 ID、阶段、状态码、耗时和安全错误类别。

## 12. UI 与文案

主要状态只使用四种短标签：

- “仅存在此浏览器”
- “等待同步”
- “已同步”
- “需要处理”

同步和容量信息应在手机窄屏上保持单列、大触控区和短句。具体安装教程继续使用步骤图与手机界面示意图，避免大段说明文字。

后续 PPT 必须包含一页“登不登录有什么区别”：用设备与云朵示意图说明本地保存、多端同步、换设备恢复和清除浏览器数据风险，不使用 Supabase 技术术语作为主标题。

## 13. 部署与运营

- 第一阶段使用一个由 Later Space 维护的统一 Supabase 项目。
- 内部测试可以使用 Supabase 默认邮件服务；对公众开放注册前必须配置可控的事务邮件 SMTP、发件域名和登录回调地址。
- 免费项目使用量达到 70% 时开始评估清理或升级，不等到 85% 才决策。
- 升级 Supabase Pro 后，将系统总图片额度配置为套餐可用空间，但仍保留 85% 产品上限和 Spend Cap。
- “连接自己的 Supabase”作为未来高级功能，不出现在第一版注册流程。

## 14. 测试与验收

### 14.1 自动测试

- RLS：两个账号不能互读、互写内容、媒体、用量和密钥。
- Auth：Magic Link 注册、登录、刷新、过期和退出。
- 工作区：guest、两个不同账号和退出后的数据完全隔离。
- 迁移：默认启动、续传、取消、撤销、重复登录不重复导入。
- 同步：离线新增、联网补传、并发编辑、删除优先和 Realtime 失败回退。
- 图片：方向修正、1920 px 限制、体积限制、元数据移除和导出一致性。
- 容量：70%/80% 提醒、85% 拒绝、并发上传、删除后恢复和总量校准。
- 快捷收件：链接、纯文字、PNG/JPEG、Safari 网页、无效密钥、撤销密钥、重复内容和真实错误通知。

### 14.2 手工验收

使用一台 Mac 和一台 iPhone 完成：

1. 未登录收藏三种内容，关闭并重开网页，确认仍在本机。
2. 邮箱登录，观察自动迁移、取消和撤销入口。
3. 在手机流量网络下分享链接、文字和图片，Mac 关机时仍能成功。
4. 打开 Mac 网页，确认新内容通过 Realtime 或焦点刷新出现。
5. 断网收藏，再联网，确认从“等待同步”变为“已同步”。
6. 退出账号，确认账号缓存不再显示；重新登录后从云端恢复。
7. 人为把个人和系统用量推到各阈值，确认提醒、阻止和删除后恢复。
8. 导出图片，确认得到清晰优化版且界面没有“原图”承诺。

## 15. 实施边界

现有 Email Magic Link、`later_space_items`、RLS、私有 Storage 和本地 IndexedDB 代码继续复用。实施需要重点替换：

- 当前首次登录的阻断式 `confirm`，改为默认后台迁移和可取消/撤销状态。
- 当前不分工作区的 IndexedDB 记录，改为 guest/user 隔离。
- 当前直接上传原始媒体的路径，改为优化、容量检查和计量一致的上传路径。
- 当前仅清除 session 的退出逻辑，改为清理账号本机缓存后切回 guest。
- 当前依赖 Mac `/api/inbox` 的手机入口，改为 Supabase Edge Function。
- 当前固定成功通知，改为展示服务端真实响应。

实现时不得覆盖或删除仓库中与本设计无关的既有用户改动。
